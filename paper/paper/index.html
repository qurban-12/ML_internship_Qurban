Prioritizing Content with Observed Impression Decline

A machine-learning decision-support study using search-content performance data

Author: Qurban Ali Rajar

Abstract

This study investigates whether search content with an observed impression decline can be prioritized for review using machine-learning ranking. The analysis uses 30,000 prepared content records covering 32 clients and evaluates search, competition, content, traffic, engagement, and freshness features. Two validation designs were compared: a standard random row split and a stricter client-grouped split in which test clients were completely unseen during training. The client-grouped evaluation achieved a ROC-AUC of 0.6157, with precision of 0.70, 0.72, and 0.70 among the top 20, 50, and 100 ranked records respectively. The results provide a directional ranking signal for review prioritization, but the model should be used as decision support rather than as an automatic predictor or decision-maker.

1. Introduction / Problem Statement

Content performance can change over time, creating a need to identify records that may require closer review. The goal of this study is to investigate whether machine-learning features can help prioritize content with an observed decline in impressions.

The research question is: Can search content that is likely to experience an impression decline be identified early enough to help prioritize content-review and refresh efforts, and does the model generalize to clients that were not seen during training?

The model is intended as a decision-support tool. A higher model score indicates that an item receives a higher ranking for review, but it does not guarantee that the content will decline or that a refresh will improve performance.

2. Data

This study uses the prepared feature dataset from the FlyRank ML Internship dataset. The analysis contains 30,000 prepared content records covering 32 clients.

The prepared dataset contains search, competition, content, traffic, engagement, freshness, and trend-related fields. The main observation windows include 90-day aggregate performance measures and separate recent and previous 30-day impression windows used to define the observed trend label.

Records were restricted to content with more than zero impressions in the 90-day window and at least 90 days of content age. Duplicate content_id records were removed.

3. Methodology

Features

The model uses 26 features covering search demand, competition, content characteristics, traffic, engagement, freshness, and content categories. Numeric features include search volume, competition, word count, 90-day impressions and clicks, content age, CTR, average position, engagement rate, and scroll rate.

Categorical features include competition level, content type, main intent, age tier, freshness tier, word-count tier, impression tier, and position tier.

Label Definition

The target is is_declining_label. A record is labeled 1 when its observed impression trend is classified as down. The trend is calculated from the difference between recent and previous 30-day impression windows. A decline is defined when the change is below -20%.

Baseline

The main baseline is random performance, represented by an ROC-AUC of 0.50. Ranking precision is also measured at the top 20, 50, and 100 records.

Validation Design

A random row split used 24,000 training rows and 6,000 test rows. This split had 31 clients represented in both training and test data.

The primary evaluation used a client-grouped split. It trained on 23,837 records from 25 clients and tested on 6,163 records from 7 completely unseen clients. There were zero shared clients between training and test sets.

Leakage Checks

Label-derived fields such as trend_direction and trend_pct were excluded from the model. A deliberate leakage test produced ROC-AUC of 1.00 when label-derived information was included, compared with 0.6157 for the clean model.

The model features contained no missing values in the final prepared dataset.

One temporal limitation remains: several model inputs are 90-day aggregate metrics, while the observed decline label is constructed from recent and previous 30-day windows. These periods can overlap. Therefore, the current evaluation measures classification of an observed decline rather than proving completely future prediction.

Interpretation

The results show that the model provides some ranking signal for prioritizing content review, but the evidence does not support treating it as a strong standalone predictor. Its most appropriate use is decision support: ranking content for human review rather than automatically deciding which content should be refreshed.

5. Limitations

Client Generalization

Performance is lower when clients are completely separated between training and test data. The random row split achieved 0.7106 ROC-AUC, while the client-grouped split achieved 0.6157.

Temporal Limitation

The model uses several 90-day aggregate performance features while the decline label is constructed from recent and previous 30-day impression windows. These periods can overlap.

Moderate Predictive Signal

The client-grouped ROC-AUC of 0.6157 is above the 0.50 random baseline but remains modest.

False Positives and False Negatives

In the client-grouped test set, there were 3,014 false positives and 3,149 false negatives. Some content ranked for review will therefore not be declining, while some declining content will not receive a high ranking.

Dataset Scope

The analysis is based on the available internship dataset and its observed search-content performance fields. The findings should not automatically be generalized to every website, industry, search environment, or future time period.

Future Validation

A stronger future experiment would use strictly time-separated feature and outcome windows, evaluate multiple future periods, and test the model on additional unseen clients.

6. Ranked Recommendations

1. Review the highest-ranked content first

Start with the top-ranked records because the model identified a higher concentration of observed declining content among them. In the client-grouped test set, 70% of the top 20 ranked records were declining.

2. Check recent performance and search visibility

Review recent impressions, clicks, CTR, average position, and engagement indicators before making a content change.

3. Prioritize content with sufficient history

The prepared dataset requires at least 90 days of content age and more than zero 90-day impressions. Similar screening conditions should be considered when applying this workflow.

4. Investigate the cause before refreshing

A high model score provides prioritization signal, not the reason for decline. Review search intent, content relevance, freshness, ranking position, and recent traffic changes before selecting an intervention.

5. Keep human review in the loop

Because the model produces both false positives and false negatives, the ranking should not automatically trigger content changes.

Rank → Review → Diagnose → Prioritize → Act → Measure

The model provides the ranking step. Human analysis determines whether an intervention is appropriate, and subsequent performance should be measured separately.
